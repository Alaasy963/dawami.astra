# المرحلة 1 — حالة التنفيذ

26 أكتوبر 2026 — نُشرت نسخة تجربة مستقلة على Cloudflare باسم dawami.v2. تفاصيلها وحدودها في DEPLOYMENT-V2.md؛ قبول المرحلة النهائي ما زال معلقاً.

## المنفّذ والمختبر محلياً

- مراجعة حضور الأوفلاين: قائمة ضمن نطاق المدير، سبب إلزامي للاعتماد/الرفض، منع مراجعة النفس، وقرار واحد محفوظ ذرياً مع الحضور والتدقيق والإشعار الداخلي. منع تداخل الجلسات واعتماد الحدث مرتين. الأحداث القديمة بلا سياق جهاز/فرع كافٍ قابلة للرفض فقط.
- حفظ سياق الفرع والجهاز وقت وصول الحدث، وإرجاع القرار النهائي للعامل عند المزامنة. إعادة إرسال الطلب بعد انقطاع الرد تحافظ على بياناته الأصلية ومعرّفه.
- حماية ربط الأجهزة: جهاز واحد لهوية واحدة داخل الشركة، وحسم الطلب مرة واحدة وإلغاء الطلبات المعلقة الأخرى لنفس العضوية. لا تُحذف سجلات مكررة تلقائياً عند الترحيل؛ التكرار القديم يوقف الترحيل للمراجعة.
- حجز outbox مؤقتاً أثناء الإرسال، مهلة اتصال وإعادة المحاولة. اختبار محاولتي إرسال متزامنتين أعطى إرسالاً واحداً. تسليم الشبكة يظل at-least-once إذا وصل الإشعار ثم تعطّل الخادم قبل حفظ النتيجة؛ لا وعد بمنع التكرار الخارجي تماماً.
- اشتراك Push لنفس الهوية في أكثر من شركة على نفس الجهاز، ومنع مشاركة endpoint بين هويتين مختلفتين.
- شعار الشركة: تصغير الصورة بالمتصفح، حدود الحجم والنوع بالخادم، تخزين R2 وقراءة خاصة بعضوية الشركة وسجل تدقيق. الصور القديمة تبقى محفوظة مؤقتاً لتجنب حذف نتيجة رفع متزامن.
- زر عربي/English مع RTL/LTR وتواريخ بحسب اللغة، وقاموس نصوص الواجهة ورسائل الخطأ المعروفة. أسماء الأشخاص والشركات والمحتوى الذي يكتبه المستخدم لا تترجم تلقائياً. نصوص Push المخزّنة بالخادم تبقى عربية حالياً.
- الوضع الخفيف يقلل المؤثرات ويؤجل تحميل الخريطة حتى الطلب. أيقونات PNG وApple touch icon للتثبيت.
- تجديد جلسة كسول عند تحديث الهوية، فقط للشركة الفعالة والعضوية المؤهلة، دون كتابة KV عند كل طلب.

## أدلة التحقق

- `npm test`: 34 اختباراً ناجحاً ضمن 9 ملفات، تتضمن سيناريو API متعدد الخطوات مع SQLite مؤقتة وKV/rate/R2 تجريبية. يشمل شركتين، مدير فرع ونطاقه، PIN والاستعادة، CSRF، القفل، مراجعة الحضور، التدقيق، الشعارات، تزامن outbox، ومفاتيح الترجمة.
- `npm run build`: TypeScript وVite وWorkbox. كاش الواجهة دون API أو tiles الخرائط.
- ترحيلات D1 المحلية 0002–0008 طُبقت بنجاح، بما فيها فصل اشتراكات Push.
- اختبارات SQLite لا تثبت سلوك KV المتوزع أو حدود rate binding أو أداء scrypt على Workers.

## المتبقي قبل قبول المرحلة

1. فحص بصري ووظيفي بالمتصفح على 360px وباللغتين، والتباين والتثبيت والأوفلاين بعد إعادة الفتح. المتصفح المحلي انتهى بمهلة اتصال؛ لا توجد معاينة بصرية موثوقة لهذه الدفعة.
2. اكتمل D1/KV/R2 وVAPID، وأكد المستخدم Push والشعار. قياس 27 أكتوبر أظهر CPU=175ms للدخول مقابل حد Free=10ms؛ حسم هذا المانع مطلوب قبل الإنتاج. تفاصيل وأدلة في PHASE-1-FINAL-REVIEW.md.
3. قرار المستخدم المعتمد: المدير العام لا يحتاج مراجعة لحضوره الأوفلاين ضمن شركة فعالة؛ يُحفظ وقت الحدث بعد فحوص الجهاز والموقع والتوقيت والتداخل. مدراء الفروع/الأقسام يبقون بحاجة لمراجعة المدير العام. الوصول بعد قفل الشركة يبقى غير معتمد وفق القرار السابق. اختُبر المساران مع رفض المستقبل والخروج قبل الدخول.
4. اختبار جميع المسارات بالموبايل، وتحسين أي عيوب تظهر قبل الانتقال للمرحلة الثانية. توسيع الترجمة لإشعارات الخادم لاحقاً إذا تقرر إرسالها بلغة المستلم.

## قبول المستخدم لمسار الحضور

26 أكتوبر 2026: أكد المستخدم نجاح تسجيل الدخول والخروج من الحضور على الموبايل داخل نطاق الفرع بعد تعيينه. وأكد سابقاً إعداد حساب مالك المنصة وتسجيل الدخول. هذه نتيجة لمسار الحضور المتصل؛ لا تثبت الأوفلاين أو Push. أضيف تمييز رفض الإذن عن عدم توفر GPS وانتهاء المهلة، مع إرشادات عربية/إنكليزية واختبارات للنتائج الثلاث والمتصفح غير الداعم وحفظ إحداثيات النجاح.

### إصلاح استعادة الجلسة دون إنترنت

أبلغ المستخدم أن إعادة فتح التطبيق أوفلاين أعادته للدخول. السبب المؤكد في الكود: الاعتماد على sessionStorage. نُقلت لقطة العضوية المرتبطة بالجهاز إلى localStorage دون CSRF أو قائمة العضويات، مع فحص الانتهاء وإزالة اللقطة بعد تسجيل الخروج المؤكد و401/403. فشل الشبكة يستعيد اللقطة حتى لو أبلغ navigator.onLine عن اتصال. أزرار الحضور تعتمد حالة اتصال التطبيق، ونجاح الحفظ المحلي لا يتبعه تحديث خادم يطمس الرسالة. 30 اختباراً ناجحاً تشمل استعادة بعد فقد جلسة التبويب وحالات المنع. يلزم إعادة تجربة iPhone بعد تحميل النسخة الجديدة متصلاً مرة واحدة. لا يوجد تسجيل دخول جديد بكلمة السر دون إنترنت.

### عداد الحضور المحلي

أكد المستخدم ظهور رسالة حفظ الحضور أوفلاين وعودة العداد للوقت الصحيح بعد الاتصال. عولج اعتماد العداد على سجل الخادم فقط: يعكس العمليات المحلية المرتبة زمنياً كوقت مؤقت، مع العودة لوقت الخادم بعد المزامنة واستبعاد العمليات المرفوضة. أوقف جلب سجل الحضور أثناء الأوفلاين وإظهار خطأ الشبكة الخام. الاختبارات تغطي الدخول والخروج المحليين والاسترجاع والتسوية مع الخادم والمدد فوق 24 ساعة. تأكيد تجربة الآيفون لهذا العرض الجديد ما زال مطلوباً.

## قبول الأوفلاين وتجهيز اختبار Push

أكد المستخدم نجاح العداد دون إنترنت واختفاء Load failed بعد التحديث. تم تجهيز تفعيل Push بتحميل VAPID وServiceWorker مسبقاً، ثم استدعاء subscribe مباشرة عند النقر وفق متطلبات Safari. زر إشعار تجريبي يجدول رسالة لعضوية المستخدم وشركته فقط بعد التأكد من وجود اشتراك؛ لا يمثل نجاح الجدولة تأكيد وصول. اختبارات API تحقق غياب الإعداد/الاشتراك وعدم قبول مستلم يمرره العميل. يبقى وصول الإشعار الفعلي بحاجة لتأكيد المستخدم.
