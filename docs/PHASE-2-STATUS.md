# المرحلة الثانية — الدوام والشفتات

بدأت بطلب المستخدم في 29 أكتوبر 2026. يستمر التطوير على Cloudflare Free.

## القرارات

- وافق المستخدم صراحة على خصم الاستراحة مرة واحدة من مجموع جلسات يوم الدوام، فقط عند تجاوز الحد الافتراضي 6 ساعات؛ الحد قابل للإعداد.
- مدة الاستراحة يحددها المدير، وصفر حتى يضبطها.
- الإضافي بعد الاستراحة مقابل الهدف اليومي أو الأسبوعي، دون جمع إضافي يومي وأسبوعي لنفس الوقت.
- ما زال سؤالا تطبيق هامش التأخير والغياب دون شفت/مع طلب معلق بانتظار الإجابة؛ لم تُنفذ افتراضات لهما.

## المنفذ في الدفعة الأولى

packages/domain/work-time.ts: تحقق قوالب الوقت HH:mm، وتمثيل عبور منتصف الليل بإزاحة يوم مع إبقاء وردية 00:00–08:00 في تاريخها. يرفض الوقت المتساوي لأنه ملتبس بين صفر و24 ساعة.

حساب مدد الجلسات المغلقة بوقت فعلي بالميلي ثانية، مع دمج التداخل لمنع تكرار الزمن؛ خصم واحد محدود بالمدة الفعلية، ومقارنة الهدف بوضع يومي أو أسبوعي صريح. الدوال لا تجلب الحضور أو تقر اعتماده؛ مسؤولية الاستدعاء تمرير الجلسات المقبولة ليوم منطقي واحد. مدد القالب أوقات محلية اسمية وليست تحويل منطقة زمنية. اختبار تغيّر التوقيت يغطي فرق الطوابع الزمنية فقط.

80 اختباراً ناجحاً ضمن 13 ملفاً، منها 21 حالة جديدة؛ TypeScript والبناء ناجحان. الكود أساس داخلي غير مربوط بالواجهة أو API بعد، لذلك لا نشر أو تغيير لبيانات الحضور الفعلية في هذه الدفعة.

## ترتيب الإكمال وحدود التسليم

1. تخزين نسخ مؤرخة لقوالب الشفت وخطط الأعضاء مع عزل الشركة ونطاق المدير وسجل الرقابة. تعديل القالب لا يعيد احتساب الماضي بصمت.
2. API وواجهة إنشاء القوالب وتعيين جدول أسبوعي أو أوقات خاصة أو هدف ساعات؛ عرض خطة العامل وإشعاره بالتغيير.
3. تحويل تاريخ الخطة والمنطقة الزمنية إلى حدود فعلية مع معالجة أوقات التوقيت الصيفي الملتبسة/المفقودة، وربط جلسات الليل دون فصلها عند منتصف الليل.
4. دمج الحسابات والسياسات المعتمدة وتقويم الساعات والمقارنة الأسبوعية.
5. الإدخال اليدوي والتعبئة والاعتماد وتذكير نهاية الشفت، ثم اختبارات العزل والنطاق والواجهات والقبول للشفت الليلي.

تُسجل دفعات التنفيذ مقابل هذه القائمة. لا نعود إلى دورة تحسينات مفتوحة في المرحلة الأولى إلا لإصلاح عطل مؤثر.
